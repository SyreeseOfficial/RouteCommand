## Bugs / reliability
- [ ] **[H] "Submit Another Expense" wipes the date and the default vehicle.** The receipt date is filled by JS (`receipt-date.value = today()`, `app.js:loadPersistedData`) and the vehicle by `vehicle-tag.value = savedVehicle`, but the "Submit Another" handler calls `expenseForm.reset()` (`js/receipts.js:137`), which restores the HTML defaults: date goes **empty** (a required field, so the second receipt of the day fails validation with "Enter the date on the receipt"), vehicle goes back to `N/A`. Reps who log several receipts in a row (fuel, tolls) hit this every time. Fix: after `reset()`, set the date to `today()` and the vehicle to the saved default (the credit form already does this in `resetCreditForm`).
- [ ] **[L]** Dates are set once at load. An app left open overnight (installed PWAs stay alive for days) still has yesterday's date prefilled on Receipts and Credits. Re-set the date on `visibilitychange` → visible when the field is untouched (or when the day rolled over).

## UI / UX (new; the existing "UI/UX ideas" list is not repeated)
Added 2026-10-09 from a read-through of `style.css`, `index.html` and `js/*.js` (code review only, no on-device screenshots). Ordered by how much each one contributes to the "works but not polished" feeling. The first five are the likely culprits.

### Why it feels off (do these first)
- [x] **[H] Everything animates at 0.3 s.** `--transition: 0.3s ease-out` (`style.css:49`) is used for every hover, press, focus and color change. Native-feeling apps use ~0.12-0.15 s for state changes. At 0.3 s a tap on a pill toggle, nav item or button lags behind the finger, and the focus border on inputs fades in slowly while typing. Add `--transition-fast: 0.15s ease-out` for color/border/background/transform, keep 0.3 s only for the drawer/modal slides. **Done 2026-10-09.**
- [x] **[H] Tab switches feel slow and slightly janky.** `navigateTo` calls `window.scrollTo(0, 0)` (`js/nav.js:40`) while `html { scroll-behavior: smooth }` (`style.css:79`), so each tab change visibly *scrolls* up while the new view fades and slides in (`fadeSlideUp` 0.35 s). On a first visit to a tab the form card then fades in again on top of that (`.form-card` opacity 0 → 1 with 0.1 s delay, `style.css:407-421`), so the card is blank for about half a second. Use `scrollTo({ top: 0, behavior: 'instant' })`, drop the card entrance animation (or the view one, not both), and keep the card visible from the start. **Done 2026-10-09.**
- [x] **[H] Buttons grow on hover and stay grown on phones.** `.btn--red`, `.btn--gold`, `.btn--outline` use `transform: scale(1.02)` on `:hover` (`style.css:550-596`). On touch, hover sticks after a tap, so full-width buttons stay 2% wider than the card padding and bump into the card edge. Remove the hover scale (keep the `:active` press), and wrap hover styles in `@media (hover: hover)`. **Done 2026-10-09.**
- [x] **[H] No icon, manifest or safe-area handling, so the installed app looks like a web page.** `index.html` has no `<link rel="icon">`, no `apple-touch-icon`, no web app manifest, and no `viewport-fit=cover`; `style.css` has no `env(safe-area-inset-*)`. Result: browser tab shows a blank default icon; "Add to Home Screen" gives a letter or page screenshot instead of the shield; on iPhone in standalone mode the bottom nav sits under the home indicator and the header under the status bar. Fix: export the shield SVG to 180/192/512 px PNGs, add `manifest.webmanifest` (`display: standalone`, `theme_color`, `background_color`), add `viewport-fit=cover`, and pad `.bottom-nav` / `.mobile-header` with `env(safe-area-inset-bottom/top)`. Also makes the existing "Install to Home Screen" button truthful on Android (Chrome only offers the real install with a manifest). **Done 2026-10-09.**
- [x] **[H] Native controls ignore dark mode.** There is no `color-scheme` anywhere (`<meta name="color-scheme">` or `color-scheme: dark` on `:root`/`html.light`). In dark theme the date picker popup, select dropdowns, scrollbars, number spinners and the calendar icon inside `type="date"` render in light/default colors, which is the most "web form" part of the UI. Add `:root { color-scheme: dark } html.light { color-scheme: light }`. One line each. **Done 2026-10-09.**

### Visual consistency
- [ ] **[M] Too many near-identical font sizes.** Sizes in use: 0.6875, 0.7, 0.75, 0.8125, 0.875, 0.9, 0.9375, 1, 1.125, 1.375, 1.5, 1.625 rem. Pairs like 0.875 / 0.9 / 0.9375 are visually indistinguishable but make the hierarchy feel arbitrary (`.history-label 0.9rem`, `.credit-success-item__product 0.9rem`, `.bookmark-step p 0.9rem` vs the 0.875/0.9375 used everywhere else). Define 5 tokens (`--fs-xs .75`, `--fs-sm .875`, `--fs-md 1`, `--fs-lg 1.25`, `--fs-xl 1.625`) and snap everything to them. Nothing below 12 px (`0.6875rem` badges/nav labels, `0.7rem` history status are 11 px, too small for the main status indicator).
- [ ] **[M] The single-item credit/donation card is misaligned.** The first item's remove button is `visibility: hidden` (`style.css:1674`), so it still takes 44 px + gap, and the Retail/Chub toggle (`flex: 1`) ends ~52 px short of the inputs below it. Looks like a layout bug on the most common case (one item). Use `display: none` instead of `visibility: hidden` for `.credit-item__remove--hidden`.
- [ ] **[M] Credits and Donations item cards use different layouts for the same fields.** Credits: quantity stepper on the *right* (`1fr 132px`), no label. Donations: quantity on the *left* (`148px 1fr`) with a small "QTY" label, plus a labeled "SELL-BY DATE". Same widgets, mirrored positions, one labeled and one not, and two near-duplicate CSS blocks (`.credit-item` / `.donation-item`). Pick one (labeled, qty on the right) and share one `.item-card` class.
- [ ] **[M] Placeholders are doing the work of labels inside item cards.** "UPC / Item #", "Weight (lbs)", the reason `<select>` and "Search item or UPC…" have no visible label, so once the field has text you cannot tell what it is (the reason dropdown never had a label). Add small uppercase labels like the donation "QTY" one, or at least a floating label. Also helps the inline error messages make sense.
- [ ] **[M] Primary and destructive both use the brand red.** The Submit CTA, the confirm button for "Delete"/"Clear" (`confirmDialog(..., danger=true)` swaps to `.btn--red`), nav badge, error borders and the "Reset" button all read as the same red, so "go" and "careful" look alike. Keep red for the CTA, and make destructive actions a clearly different treatment (outlined `btn--danger-outline` everywhere, or the existing `--color-error` #cf4444 filled). Also set initial focus in the confirm dialog on **Cancel** when `danger` is true; today `ok.focus()` lands on the destructive button (`js/util.js:104`).
- [ ] **[M] Disabled/submitting button turns grey.** `.btn--red:disabled` is `#555` (`style.css:560`). During "Submitting…" and "Processing photo…" the main button goes dull grey with a spinner, which reads as "broken" rather than "working". Keep the red, use `opacity: .7` and `cursor: progress`; reserve grey for truly unavailable states.
- [ ] **[M] Status shown as tiny plain text, not a badge.** History rows show `SAVED / QUEUED / FAILED` as 11 px colored text next to the type, while the rest of the app uses pill badges (`.credit-success-item__reason`, `.expiring-tag`). A failed row is the most important thing on that screen and is the least visible. Use a pill with an icon (check / clock / !) and a left accent bar on the card for failed/queued rows.
- [ ] **[M] Form field borders and focus ring are too faint on dark.** Input border `#222` on a `#161616` card is ~1.1:1, and the focus color `--color-red` `#841b2a` on `#161616` is about 1.9:1 (below the 3:1 WCAG asks for UI components). The inputs are identifiable only because they are black wells. Lift the default border to ~`#3a3a3a`, and make focus a brighter border (`--color-red-text` or the gold-text color) plus the existing glow. The global `:focus-visible` outline is fine but inputs set `outline: none`, so keyboard users get the weak red only.
- [ ] **[M] Muted text fails contrast.** `--color-muted #555` is used for real text (`.gatekeeper__credit`, `.settings-branding`, `.history-empty` hint inherits subtext, ok) on black = ~2.8:1. Use `--color-subtext` for text and keep `--color-muted` for borders/disabled only.
- [ ] **[M] Light mode is an afterthought.** Many styles use `rgba(255,255,255,0.0x)` for backgrounds, hovers and dividers (`.nav-item:hover`, `.credit-item` and `.donation-item` backgrounds, `.store-suggestion` separators, `.qty-stepper__btn:hover`, `.drawer__item:hover`, `.modal__close:hover`). On white they are invisible, so cards lose their inset look and hovers do nothing. Also `.map-placeholder` / `.video-thumb` are hardcoded `#1a1a1a`. Replace with a `--color-hover: rgba(255,255,255,.05)` token that `html.light` redefines as `rgba(0,0,0,.05)`.
- [ ] **[L] Success check is dark-gold on near-black.** `#625636` check on `#161616` is ~2.5:1 (`index.html` success icons), and green `--color-success` exists but is unused there. A confirmation moment should be the most legible thing on the screen. Use green (or the lighter `--color-gold-text`) for the check, and drop the three duplicated inline SVGs for one `<symbol>`.
- [ ] **[L] Radii and borders mix too many shapes.** Inputs/buttons 6 px, items 10 px, cards 16 px, pills 100 px, toggle 100 px; fine in isolation but buttons (6 px) inside cards (16 px) inside a 10 px item card look unrelated. Consider 8 px for controls and 12 px for cards.

### Flow and feedback
- [ ] **[M] "Saved Offline" looks identical to "Success".** `showSuccess(queued)` (`js/submit.js:34`) only swaps the title and message; the same check-in-circle icon stays. A rep glancing at the screen can think it already reached Ian. Use a different icon (cloud/clock) and the gold color for the queued state, keep the check for confirmed sends.
- [ ] **[M] Success copy is inconsistent.** "Upload Successful!" (receipt, but it is not just an upload), "Credits Submitted!", "Donation Logged!". Receipts and Credits say "Ian has your …", Donations says "The donation pile has been recorded." Pick one pattern ("Receipt sent", "Credit request sent", "Donation logged") and drop the exclamation marks for a calmer, more professional tone.
- [ ] **[M] After success, both buttons look the same.** "View in history" and "Submit Another …" are both full-width outlines (`index.html:218-219`). The likely next action (another one) should be primary, history a text link or secondary.
- [ ] **[M] The app never says who you are.** The name is used on every submission but only visible in Settings; the header is just the logo. On shared or loaner phones, or after the name gate, nothing confirms the right person is active. Show the name (and online/queued state) in the mobile header's right side and at the bottom of the desktop sidebar; tap goes to Settings.
- [ ] **[L] Restored drafts are silent.** Credits/Donations forms reload pre-filled from localStorage (`autosaveDraft`/`loadDraft`) with no message, so an old half-filled form can look like a bug or a leftover. Show "Draft restored · Clear" once at the top of the form.
- [ ] **[L] Vehicle Tag pops in and out.** Choosing Fuel/Maintenance/Tolls inserts a field right under the control the finger is on and shoves everything down (`display: none` toggle, `js/receipts.js:70`). Animate the height, or reserve the space.
- [ ] **[L] Toast and update banner overlap, with no enter/exit motion.** `.toast` and `.tip` share the same fixed position and z-index (`style.css:2053`, `2114`), so an "Update available" banner and a toast cover each other. Both just pop via `.hidden` with no fade. On desktop (≥1024 px) they float 76 px above the bottom for a nav that is not there. Stack them in one container, add a 150 ms fade/slide, and offset by `--bottom-nav-h` only on mobile.
- [ ] **[L] Modals have no exit animation or focus trap.** Open slides up; close is an instant `display: none`. Tab can escape the dialog to the page behind. Use native `<dialog>` (already used for the photo viewer) for the confirm and install modals; it gives you the focus trap, Escape and a backdrop for free.
- [ ] **[L] No empty/loading/no-result states in search.** Typing a store or item with no match just shows nothing. Show "No match. Check the spelling or use the exact store name" (and for items, "Use as typed"); there is also no loading hint on the first search while `data.json` downloads.
- [ ] **[L] History silently drops anything past 15 rows** (`history.length = Math.min(..., 15)`, `js/history.js:29`) while the subtitle says "Recent submissions from this device". Say "Last 15" in the subtitle, or raise the cap (rows are small).
- [ ] **[L] Pull-to-refresh is undiscoverable.** The only cue is a 12 px text prefix "Release to refresh ·" while pulling (`style.css:2145`). Add a small arrow/spinner that grows with the pull, or a visible "Send now" button in the "Last sent" line when something is queued.

### Navigation and structure
- [ ] **[M] Active tab is shown only by color.** Bottom nav active state is a red-tinted icon and label with no indicator shape (`style.css:1029`), 11 px labels and 22 px icons; on a dark bar the difference between `#a0a0a0` and the red tint is subtle, and fails for color-blind users. Add a pill behind the icon (like Material 3) or a 2 px top bar, bump labels to 12 px, and set `aria-current="page"` on the active button (nav buttons currently expose no state to screen readers; pill toggles also need `aria-pressed`).
- [ ] **[M] Settings has two overlapping "add to home screen" blocks.** The "Install to Home Screen" card (opens a modal with iOS/Android steps) and the "Save to Your Phone" accordion (iOS/Android × home screen/bookmark) teach the same thing in two UIs, and the accordion is styled as a big `.form-card` (1.75 rem padding, heavy shadow) next to flat `.settings-card`s. Merge into one card; hide it entirely when `isStandalone()` is true (`js/settings.js:62` exists).
- [ ] **[L] Settings cards use two label styles.** `.settings-card__label` (uppercase 13 px grey) vs `.form-label` (normal 13 px white) for the same job (labeling a select). Pick one.
- [ ] **[L] Desktop layout is left-heavy.** `.main-content` is `margin: 0 auto` then `margin-left: 260px` at ≥1024 px with `max-width: 980px`, so on a 1440 px monitor the 720 px column hugs the sidebar and leaves ~460 px of empty space on the right. Center the column in the remaining area (`margin-inline: auto` inside a `padding-left: 260px` wrapper). Low priority if reps use phones.
- [ ] **[L] Small touch targets.** `.modal__close` and `.tip__close` are 32 px; the photo thumbnail "tap to enlarge" target is 72 px but has no visible affordance (no zoom icon). Raise the close buttons to 44 px.
- [ ] **[L] Tap highlight flashes on Android.** `-webkit-tap-highlight-color: transparent` is set on six selectors only; `.btn`, `.nav-item`, `.upload-btn`, `.history` buttons show the default grey flash. Set it once on `button, label, summary`.
- [ ] **[L] Passcode screen: infinite `drop-shadow` pulse.** `shieldPulse` animates `filter: drop-shadow(...)` forever (`style.css:214`); filter animation repaints each frame and drains battery on the screen reps hit every cold start. Animate `opacity` on a pseudo-element glow instead, or stop after 2-3 loops.
- [ ] **[L] Photo buttons are lopsided.** "Take Photo" has an icon, "Choose from Library" has none, so the pair looks unfinished. Add a gallery icon, make "Take Photo" the filled/primary one. The preview should also offer "Remove", not only "Retake".
- [ ] **[L] Category dropdown for the most common choices.** Fuel and Sales Lunch are probably most receipts, but each needs open-select → scroll → tap. Optional: show the top 3 (last used) as chips above the select.

### Round 2 (added 2026-10-09, second pass: palette, mobile keyboard, flows, copy, a11y)

**Look and depth**
- [ ] **[M] No sense of depth: black cards on a black page.** Page `#000`, card `#161616`, border `#222`, shadow `rgba(0,0,0,.5)` (`style.css:9-16, 45`). A black shadow on a black background is invisible, so cards and the sticky bars read as flat rectangles outlined by faint lines. Make elevation come from lighter surfaces instead: page `#0b0b0b`, card `#161616`, raised (item cards, dropdowns, modals) `#1f1f1f`, with a 1 px top highlight (`inset 0 1px 0 rgba(255,255,255,.04)`). Dropdowns and modals are the ones that need to look "above" the page.
- [ ] **[M] The brand colors are too dull to carry a dark UI.** Gold `#625636` is about 2.6:1 on black and red `#841b2a` about 1.9:1 on the card (computed). The dashed "Take Photo" border, step numbers, the drawer/handle icons and the gate's focus color are all that muddy olive-brown, so the interface has no bright accent and the only high-contrast element is white text. That monotone is probably a big part of the "something is off" feeling. Keep the brand values for fills and logos, but add brighter accent tokens for borders, icons and focus on dark (e.g. gold `#9c8a55`, red `#c0394d`), and use them for the active nav indicator, focus rings and the upload border.
- [ ] **[L]** Two chevron styles: select arrows are an inline SVG, the Save-to-Your-Phone accordion and History rows use text glyphs `▾ ▴` (`style.css:1792, 2044`), which render differently per platform font. Use one SVG chevron.
- [ ] **[L]** History cards put the least important thing largest: type is uppercase caps, status is 11 px, but the key fact (the amount / store / item count, `.history-label`) is 14.4 px weight 500. Make the label ~1 rem / 600, put the time on the right of the same line, and reduce the caps label to a small chip.

**Mobile keyboard and typing**
- [ ] **[M] The fixed bottom nav rides above the on-screen keyboard.** On Android Chrome the layout viewport shrinks with the keyboard, so the 64 px nav (and any toast/tip) sits directly above the keyboard, taking a fifth of the little space left while the user types in a form. Hide it while a field is focused: `body:has(input:focus, select:focus, textarea:focus) .bottom-nav { display: none }` (or `<meta name="viewport" content="..., interactive-widget=resizes-content">` and hide on `focusin`).
- [ ] **[M] The keyboard's Enter key submits the whole form.** No field sets `enterkeyhint`, and the forms are plain `<form>`s, so in Credits tapping "Go/Enter" in the UPC or weight field fires `submit` on a half-filled item (the validation then scolds the user). Add `enterkeyhint="next"` to item fields (and `done` on the last), and handle Enter in item inputs as "focus the next field" (or "Add another item" from the last quantity field).
- [ ] **[L]** Wrong passcode clears the field (`app.js:attemptUnlock`), so a one-letter typo means retyping everything, with no view of what was typed. Keep the text and select it (`passcodeInput.select()`), and add a short shake on the input.
- [ ] **[L]** The name gate's Continue button silently does nothing if no name is picked (`js/settings.js:28`). Show "Choose your name" under the select.
- [ ] **[L]** Item search results are a single string like `11069 Bourbonridge Smoked Ham`. Render the number as a muted monospace prefix and the name in normal weight so rows scan (the data is already `"<upc> <name>"`, `collectDonationItems` splits it the same way). Also no way to browse: with 72 stores a rep who doesn't remember the exact name has nothing to tap. Show the last 3 stores used when the field is focused and empty.
- [ ] **[L]** A store typed that isn't in the list is accepted as-is ("Choose or type a store"), so typos reach the sheet. If the value is not an exact match for a catalog store, show "Not in the store list. Sending as typed" under the field so the rep notices.

**Flow**
- [ ] **[M] The success screen sticks.** After submitting, the "Upload Successful!" panel stays in place until "Submit Another" is tapped. Go to History, return to Receipts an hour later, and you see the old confirmation instead of a fresh form (same for Credits and Donations). Reset to the form when the user leaves the tab or after ~60 s.
- [ ] **[M] Back button walks the tab history.** Every tab tap does `history.pushState` (`js/nav.js:42`), so after browsing five tabs the Android Back button steps through each one before leaving the app, and in the installed PWA there is no other way out. Use `replaceState` for tab switches (they are peers, not drill-downs); keep `pushState` only for real sub-screens, if any.
- [ ] **[M] The "no photo" dialog nudges toward skipping the photo.** Buttons are Cancel / **Submit anyway** (the gold, primary one) (`js/receipts.js:117`). Make the primary action "Add photo" (closes the dialog and opens the camera/library), and the secondary "Submit without photo". Also, if the date is old or in the future *and* the photo is missing, the user gets two dialogs back to back; combine into one list of warnings with one confirm.
- [ ] **[M] Removing a filled item has no undo.** The × is 44 px right beside the Retail/Chub toggle, and one tap deletes the whole item (`js/itemlist.js` `[data-remove]`), including a typed UPC and quantity. Confirm only if the item has data, or show a toast "Item removed · Undo" for 5 s.
- [ ] **[L]** The donation History row label is `"<your name> · N items"` (`js/donations.js:86`). Every row on this device is your name, so it tells you nothing. Use the first item name plus a count: `Black Forest Ham +2`.
- [ ] **[L]** Settings changes save silently (name, default vehicle). Switching "Your Name" changes who every future submission is attributed to with no confirmation. Show a toast "Saved" / "Submitting as Nick now".
- [ ] **[L]** Dark Mode toggle can't go back to "follow my phone". Once toggled, the choice is stored forever (`rc_theme`). Make it a 3-way (System / Dark / Light) or remove the stored value when the toggle matches the system setting.
- [ ] **[L]** The install tip (`.tip`) stays on screen until dismissed and sits right above the nav, covering the submit button on small phones. Auto-dismiss after ~8 s, and never show it over a focused form.
- [ ] **[L]** Bookmark guide always starts on "iPhone / iOS". Preselect from the user agent (`/iPhone|iPad/` → iOS, otherwise Android).

**Copy and wording**
- [ ] **[M] The install modal's steps aren't steps.** "1. iOS Safari: …", "2. Android Chrome: …", "3. Confirm the prompt" (`index.html:492-503`) read as a sequence, but 1 and 2 are alternatives for different phones. Show only the current platform's steps (the Save-to-Your-Phone accordion already has that toggle; this is the third copy of the same instructions: modal, accordion, install tip). On Android, use `beforeinstallprompt` for a real one-tap install.
- [ ] **[M] Mixed capitalization on buttons and labels.** Title Case: "Take Photo", "Choose from Library", "Submit Another Expense", "+ Add Another Item", "Install to Home Screen", "Date on Receipt". Sentence case: "View in history", "Copy details", "Reset app and sign out", "Save for later (offline)", "Copy diagnostics", "Clear history", "Submit anyway". Pick sentence case (it reads as more modern and quieter) and apply it to every button, label and heading.
- [ ] **[L]** Labels are inconsistent about required vs optional: only Notes says "(Optional)", while Receipt Photo (effectively optional via the dialog) and everything else have no marker. Mark the *required* ones (or mark Photo "Recommended").
- [ ] **[L]** Page subtitles don't share a pattern: "Submit a new expense receipt." / "Submit a store credit request to Ian." / "Log items going into the donation pile." / "Recent submissions from this device." / "Manage your preferences and account." Not wrong, but a quick pass for one voice is cheap.

**Accessibility and robustness**
- [ ] **[M] The dark-mode toggle has no focus indicator.** The checkbox is `opacity:0; width:0; height:0` (`style.css:959`), so keyboard focus is invisible. Add `.toggle input:focus-visible + .toggle__track { outline: 2px solid ...; outline-offset: 2px }`.
- [ ] **[M] The receipt thumbnail is a fake button.** `<img role="button" tabindex="0">` (`index.html:198`) only has a click listener (`js/receipts.js:61`), so Enter/Space do nothing for keyboard and switch users. Wrap it in a real `<button>`. The full-size photo dialog also has no visible close control; add an × and a "Tap anywhere to close" hint.
- [ ] **[M] Donation item fields have no accessible names.** The "Qty" and "Sell-By Date" labels are `<span>`s (`js/donations.js:36-47`) so tapping them does nothing and screen readers announce an unnamed field, and the stepper `−`/`+` buttons and quantity input have no `aria-label` (credits has them, donations doesn't). Use `<label>` or `aria-label`. Same for `Receipt Photo` (`<label>` without `for`) and for all placeholder-only inputs (UPC, weight, search).
- [ ] **[L]** History day headings are `<h4>` directly under the page `<h2>`, skipping h3; use `<h3>` (or style a `<p>`). Pill toggles lack `role="group"`/`aria-pressed`, nav buttons lack `aria-current`; `<aside role="navigation">` plus an inner `<nav>` is a double landmark, and `<main role="main">` is redundant.
- [ ] **[L]** First paint is blank. `#gatekeeper` and `#app` are both `.hidden` until the module script runs, so a cold start on slow data shows an empty screen. Show the shield + "Route Command" in the HTML by default and let JS hide it, so there is never a dead frame.
- [ ] **[L]** The passcode input is `autocomplete="current-password"`, so phones offer to save the shared company passcode in the user's password manager. `autocomplete="off"` (or `one-time-code`) avoids that.

## Remove / clean up
