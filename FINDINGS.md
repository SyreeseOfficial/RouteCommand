## High value

1. [ ] **[XS]** _Security_ — The Sheet ID, Drive folder ID and the live passcode are in three tracked docs at HEAD, not just in git history. `docs/RULES.md`, `docs/PRD.md` and `docs/CHANGELOG.md` contain the Sheet/Drive IDs or the word `boarshead` (grep today); `RULES.md` even instructs "NEVER modify" the IDs. Remove them from the files, put them in the GAS Script Properties only (already the case in `Code.gs`), and rotate the passcode once it is server-side.
2. [ ] **[S]** _Data_ — Everything lives in two Google Sheets with no backup. Add a time-driven Apps Script trigger that copies each Sheet to a dated backup folder weekly (`makeCopy`) and keeps 8, plus a README note about version history; a deleted tab or mass edit is otherwise unrecoverable.
3. [ ] **[S]** _Data_ — Free-typed donation and credit items are accepted ("No match. It will be sent as typed.") and land in the Sheet with no marker, so the Sheet fills with variants of the same product and Ian can't pivot by item. Add a `Matched` column (true when the text equals a catalog entry) and a weekly list of unmatched names to fold back into `data.json`.
4. [ ] **[S]** _Reliability_ — `submit.mjs` makes two sequential `fetch` calls (POST, then the redirect target) without timeouts and with no retry; Netlify functions time out at 10 s on the free tier, which is shorter than Apps Script's typical 4-8 s cold start plus a large photo. Use `AbortSignal.timeout(8000)` per call and return a retryable status (503) so the client keeps the item queued instead of marking it failed (the older item on permanent failures needs this status).
5. [ ] **[S]** _Reliability_ — Apps Script quota is invisible: `MailApp`/`DriveApp` and 30 simultaneous executions per script, 6 min/execution, and daily Drive write limits can return HTML errors that surface as "Google is busy". Log the failure reason in `submit.mjs` (status + first 200 chars) and surface "Google daily limit reached" differently from a generic busy message.
6. [ ] **[S]** _Reliability_ — Photo upload and Sheet append are not atomic in `Code.gs`: the image is created in Drive (step 5) before `appendRow` (step 6); if the append throws (sheet protected, quota), the file is orphaned and the retry creates a second copy with the same filename. Create the file, append, and on failure `setTrashed(true)` the file; or append first with a placeholder and update the URL cell after the upload.
7. [ ] **[S]** _Reliability_ — The mobile menu uses the Popover API (`mobileMenu.hidePopover()` in `nav.js`), which needs iOS/Safari 17+; on an older iPhone every nav tap throws and the menu never closes. Feature-detect `HTMLElement.prototype.showPopover` and fall back to a `hidden` class, and note the minimum browser versions in the README.
8. [ ] **[S]** _Reliability_ — Ask the browser to keep the outbox. Unsent submissions live in IndexedDB and `localStorage`, which Safari can evict after about 7 days without use when the app isn't installed to the Home Screen, and Chrome evicts under storage pressure. Call `navigator.storage.persist()` after the first successful sign-in, show the result in Settings, and warn iOS users who haven't installed the PWA that unsent items can disappear.
9. [ ] **[S]** _Security_ — `timestamp` and `employeeName` come straight from the client and are written to the Sheet as-is (`Code.gs` payload parsing), so a direct POST can attribute a receipt to anyone and backdate it. Check `employeeName` against the roster in the GAS (store the roster in Script Properties or a Config tab) and write a server-side `new Date()` into the Timestamp column; keep the client value in a separate "Client time" column.
10. [ ] **[S]** _Security_ — Receipt photos are public-by-link and `fileName` uses the employee name and amount (`Code.gs` step 4); a link in a Sheet cell that is ever shared exposes card last-4 and names. Beyond `DOMAIN_WITH_LINK` (older item), store files in a folder-per-month and skip per-file sharing entirely, letting the Sheet viewers' folder permission decide.
11. [ ] **[S]** _Security_ — The Apps Script web apps run as the owner with "Anyone" access and no secret; the Netlify function is the only caller that should exist. Add a shared-secret header check in all three GAS scripts (`PropertiesService`), add it in `submit.mjs`, and reject requests without it (older items mention the secret; this adds the concrete header and per-script check).
12. [ ] **[?]** _Bugs and data loss_ — A new submission can silently delete an unsent failed one. `saveToHistory` drops every earlier `failed` row with the same type + label (`js/history.js:24`), and `reconcile` then deletes any `failed` outbox record that no history row points at (`js/queue.js:51`). Labels are only `$amount · category`, so two real receipts such as `$5.00 · Tolls / Parking` collide; if the first one failed, entering the second discards the first receipt and its photo with no warning. Match on `submissionId` (or a content key of date + amount + category + store), never on the label, and stop `reconcile` from deleting failed records that still hold unsent photos without asking.
13. [ ] **[?]** _Bugs and data loss_ — Transient server trouble becomes a permanent failure. `postJSON` returns only the parsed body and drops `res.status` (`js/util.js:77-90`); `flushOutbox` then treats anything other than a network error as terminal and writes `status: 'failed'` (`js/outbox.js:77-86`). So a queued submission that hits "Google is busy" (the gateway's own 502), a lock timeout ("Server busy, try again."), or a platform 504 waits for the rep to open History and tap Retry. Return `{ ok, status, body }`, keep 5xx / 429 / "busy" replies in `queued` with an `attempts` count and backoff (1 min, 5 min, 30 min), and only mark `failed` for 4xx validation errors. Resending is already safe thanks to `submissionId`.
14. [ ] **[?]** _Features_ — Email Ian on every submission. 3 lines of `MailApp.sendEmail` with a link to the Sheet row and the photo. Doubles as a backup of what was submitted.
15. [ ] **[?]** _Features_ — Warn when the amount looks wrong: confirm if `amount >= $500`, or if it equals an earlier submission today (same amount + category). Cheap guard against typos like 1250 vs 12.50 and double-submits.
16. [ ] **[?]** _Features_ — Tell reps what happened to their submission. Today every row ends at "saved" (it reached the sheet), and reps never learn if it was approved, paid, or needs another photo. Add a `Status` / `Reviewer note` column to the receipt sheet (the credits sheet already has a `Done` column), a `doGet?name=...&secret=...` endpoint returning that rep's last 30 rows, and show "Approved" / "Paid" / "Needs info: <note>" chips in History on open. This is rep-facing and distinct from the parked admin page.
17. [ ] **[?]** _Security and abuse_ — The passcode is a constant compared in the browser (`app.js:72-73`), visible in DevTools or the repo. Move the check into a Netlify function (`/api/auth`) that compares against an env var and returns a signed token (HMAC, 30-day expiry); the submit functions require that token. Combine with per-person PINs to also fix "anyone can submit as anyone".
18. [ ] **[?]** _Security and abuse_ — Securing only the Netlify function is not enough: the GAS web app URL is hardcoded in the repo history and the deployment is "Anyone". Anyone can POST straight to Google and fill your Drive folder or Sheet. Put a shared secret in a Netlify env var **and** in GAS `PropertiesService`; the function adds it to the body, `doPost` rejects when missing or wrong. Then rotate the GAS deployment URL (new deployment = new URL) and update the Netlify env vars.
19. [ ] **[?]** _Security and abuse_ — `data.json` is still published (employee full names, customer store names) and the Drive folder and Sheet IDs remain in git history. The `dist/` change already stopped the `.gs` and docs files from being downloadable. Decide if `data.json` must sit behind the auth token, and whether to rotate the IDs.
