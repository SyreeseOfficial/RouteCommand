# Route Command: Findings

Reviewed 2026-10-08. `IMPROVEMENTS.md` already tracks many items under "Later". Where this list repeats one, it is because the item should be **promoted** (marked "PROMOTE"). Everything else is new. Tags: **[H]** high, **[M]** medium, **[L]** low. `[ ]` = open.

## Security and abuse (PROMOTE these out of "Later": real company data and a public URL)
- [ ] **[H] PROMOTE** Whole repo is published. `netlify.toml` has no `publish` dir, so `Code.gs`, `CreditCode.gs`, `DonationCode.gs`, `PRD.md`, `PROMPTS.md`, `data.json` etc. are downloadable from the live site. `Code.gs:13-14` contains the Drive folder ID and Sheet ID; `data.json` has employee full names and customer store names. One fix covers it: build into `dist/` (copy only `index.html`, `app.js`, `style.css`, `sw.js`, `data.json`, icons) and set `publish = "dist"`.
- [ ] **[H]** Securing only the Netlify function is not enough: the GAS web app URL is hardcoded in `netlify/functions/submit-*.mjs`, so it is also public in the repo, and the deployment is "Anyone". Anyone can POST straight to Google and fill your Drive folder or Sheet. Put a shared secret in Netlify env **and** in GAS `PropertiesService`; the function adds it to the body, `doPost` rejects when missing/wrong. Rotate the GAS deployment URL afterwards (new deployment = new URL) and move it to a Netlify env var.
- [ ] **[H] PROMOTE** The passcode is a constant compared in the browser (`app.js:72-73`), visible to anyone who opens DevTools or the repo. Move the check into a Netlify function (`/api/auth`) that compares against an env var and returns a signed token (HMAC, 30-day expiry); the submit functions require that token. Combine with per-person PINs (from "cheap features") to also fix "anyone can submit as anyone".
- [ ] **[M]** No size/shape validation in `doPost` (`Code.gs:56-70`): `imageData` has no max length (a 50 MB base64 string will eat the daily Apps Script quota or time out), `amount` and `receiptDate` are not validated, `category` is free text. Reject images over ~2 MB decoded, require `^\d{4}-\d{2}-\d{2}$` dates, amount `> 0` and `< 10000`, and `category` in an allowlist.
- [ ] **[M]** `savedFile.setSharing(ANYONE_WITH_LINK)` (`Code.gs:90`) makes every receipt photo (names, card last-4, addresses) public to anyone with the link. If accounting sits in the same Workspace domain use `DOMAIN_WITH_LINK`, or skip per-file sharing and let the folder's permissions apply.
- [ ] **[M]** Sheet formula injection (`= + - @`) is parked but trivial: prefix with `'` in `sanitize()` (`Code.gs:163`), same in the other two `.gs` files.
- [ ] **[L]** Build command runs `npx -y esbuild` unpinned and **overwrites `app.js`/`style.css` in place** (`netlify.toml:3`). Running it locally destroys your source files, and a new esbuild release can change the output unexpectedly. Add `esbuild` as a pinned devDependency and output to `dist/`.
- [ ] **[L]** History stores rendered HTML (`summary: summaryHTML`) in localStorage and re-injects it with `innerHTML` (`app.js:~470`). Store the data and render with `esc()` at view time.
- [ ] **[L]** No rate limiting or logging on the functions. Netlify's `context.ip` + a small in-memory counter, and `console.log` of failures, gives you something to look at when a submission "went missing".

## Bugs / reliability
- [ ] **[H] PROMOTE** Duplicate rows on retry: the 20 s timeout (`postJSON`), a lost response, the queue, and "failed" retry all re-send a payload that GAS may already have saved. Add `submissionId` (`crypto.randomUUID()`) to each payload at creation; in `doPost` check a hidden "ID" column (or `CacheService`) and return the earlier success if seen. This is the single biggest data-quality fix.
- [ ] **[H]** Rows marked `sending` are flipped to `failed` on next load (`app.js:1336`). If the app was closed mid-request the server may have saved it, and the user then taps Retry and creates a duplicate. Fixed by the same `submissionId` check; until then, show "Unknown, check with Ian" instead of "failed".
- [ ] **[M]** Gateway reports `200` for every outcome and `res.json()` throws `SyntaxError` on any non-JSON reply (Google HTML error page, quota exceeded). That lands in the "failed" branch with a raw error message (`app.js:344-358`). Have `_gasProxy.mjs` return 502 with a JSON `{status:'error', message:'Google is busy, try again'}` when the body isn't JSON, and surface that text.
- [ ] **[M]** `getActiveSheet()` (`Code.gs:96`) writes to whichever tab happens to be active. Reordering tabs sends receipts to the wrong sheet silently. Use `getSheetByName('Receipts')`.
- [ ] **[M]** Header-row creation race: two simultaneous first submissions can both see `getLastRow() === 0` and write two header rows. Wrap the whole `doPost` body in `LockService.getScriptLock().waitLock(10000)`.
- [ ] **[M]** Service worker never versions: `CACHE = 'rc-v1'` is fixed (`sw.js:3`) and stale-while-revalidate serves the old `app.js` for one extra load after every deploy, with no signal to the user. Inject a build hash into the cache name at deploy and show an "Update available, tap to reload" toast on `controllerchange`.
- [ ] **[M]** Queue only flushes while the app is open (`setInterval` 30 s + `online` event). Reps in trucks and warehouses close the app and the receipt sits unsent. Register Background Sync (`registration.sync.register('flush')`, Chrome/Android) and move `flushQueue` into the service worker (needs the queue in IndexedDB).
- [ ] **[M]** Queue and history live in `localStorage` (about 5 MB): each queued receipt carries a base64 image (~150-400 KB), so about 10-20 offline receipts can fill it, and `enqueue()` then returns false and shows a generic network error. Move image blobs to IndexedDB, or warn "Queue is full, connect to send".
